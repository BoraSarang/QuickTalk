## 동작 — 시간 순서 타임라인

사고 과정과 도구 실행을 **고정 위치에 몰아넣지 않고**, 실제 일어난 순서대로 그린다.

```
질문
  › 사고 과정            ← 1번째 모델 호출의 사고
  [도구 카드] web_search
  › 사고 과정            ← 2번째 모델 호출의 사고
  [도구 카드] shell
  › 사고 과정            ← 최종 답변 직전의 사고
답변
출처(검색 결과)          ← 지금처럼 답변 하단
```

- 사고 구간은 **스텝(모델 호출) 단위**로 `AgentEvent.reasoningBefore` 에 저장한다.
  한 스텝에서 도구를 여러 개 부르면 첫 카드 앞에만 사고가 붙고 나머지는 같은 카드에 묶인다.
- 마지막 스텝의 사고는 `Turn.reasoning` 에 남는다(구버전 기록과 같은 자리).
- 구버전 기록(`reasoningBefore` 없음)은 지금까지처럼 **도구 카드 한 장**으로 보인다.

## 표시 방식 설정 (설정 › AI › 사고 과정 표시)

| 모드 | 진행 중 | 완료 후 |
| --- | --- | --- |
| `항상 보기` | 펼침 | 펼침 유지 |
| `끝나면 자동으로 접기` (기본) | 펼침 | `› 사고 과정` 한 줄 |
| `'생각 중' 표시만` | `🧠 사고 과정 — 생각 중` 한 줄 | **흔적 없음** |

- 사용자가 직접 누른 펼침/접힘 상태가 설정 기본값보다 우선한다.
- 모르는 설정 값은 기본값(`끝나면 자동으로 접기`)으로 폴백한다.

## 자동 스크롤

- 사고 텍스트가 흐르는 동안에도 바닥을 따라간다(`agentFollowToken` 에 사고 글자 수 포함).
- 사용자가 위로 올려 읽는 중이면 끌어내리지 않는다(기존 `followsBottom` 규칙 그대로).

## 지원 경로

- OpenAI 호환 SSE `delta.reasoning_content`
- Ollama NDJSON `message.thinking` / `message.reasoning_content`
- 에이전트(도구 호출) 경로 포함 — 스텝마다 구간을 나눈다.
- Apple FM 은 사고 과정을 노출하지 않는다(계약만 채움).
- 표시 상한 24,000자 — 무한 사고로 메모리가 커지지 않게 자른다.
- `[중지]`·오류·대화 전환 시 임시 사고 텍스트는 즉시 비운다.
