입력창의 ＋를 없애고, 그 자리를 Edge 패널 하나로 모읍니다. 클립보드 · 파일/이미지 · 화면 캡처가 같은 패널의 탭으로 들어가고, 캡처는 전체화면 · 윈도우 · 드래그 선택 3모드를 가집니다.

2. 범위 이번에 구성하는 것 / 나중에 붙이는 것

이번 (구성)

  • Edge 핸들 — 화면 오른쪽 끝, 클릭하면 패널
  • 패널 3탭 — 클립보드 / 파일·이미지 / 캡처
  • 클립보드 — 2분 · 5개 · 민감 마스킹 · 사용 후 소비(기존 코어 재사용)
  • 파일·이미지 — 파일 선택 · 이미지 선택 · 드래그 앤 드롭 (입력창 ＋ 대체)
  • 캡처 — 전체화면 / 윈도우 / 드래그 선택 3모드, 결과는 캡처 탭에 쌓임
  • 대화 연결 — 카드를 누르면 입력창 삽입 또는 첨부
  • 설정(핸들·폭·캡처 후 동작·단축키)

나중 (기능 추가)

  • 캡처 주석(펜·화살표·모자이크), 스크롤 캡처
  • OCR — 캡처/이미지에서 텍스트 추출
  • 캡처 지연 타이머(3·5·10초), 커서 포함
  • 파일 탭의 최근 폴더·즐겨찾기, 태그
  • 클립보드 전체 검색 레이어(T-22)
  • 패널 폭 조절·다중 모니터 위치 기억

8. 구현 메모 기술적으로 미리 짚어둘 것

중요 — macOS 기본 단축키는 가로챌 수 없다
  • ⌘⇧3·⌘⇧4는 시스템이 독점한다. 앱이 이 키를 대체하는 것은 안정적이지 않다.
  • 그래서 같은 3모드를 자체 단축키(⌥⇧3·⌥⇧4)로 제공하고, 캡처 엔진은 ScreenCaptureKit(권한: 화면 기록) 으로 구현한다.
  • 대안 1 — /usr/sbin/screencapture -i 호출: 구현은 빠르지만 우리 UI(돋보기·툴바)를 그릴 수 없다.
  • 대안 2 — 기본 단축키로 찍힌 결과를 Desktop/클립보드 감시로 주워와 QuickShelf에 넣기: 사용자는 지금 습관 그대로, 앱은 결과만 받는다. 가장 현실적.
구조
  • 핸들 = borderless NSWindow (level .statusBar, 모든 Space) · 패널 = NSPanel(.nonactivatingPanel, .floating)
  • 캡처 오버레이 = 화면별 borderless 창(어두운 층 + 선택 사각형 + 돋보기). 전체화면 앱에서는 .fullScreenAuxiliary로 위에 표시.
  • 기존 Clipboard.swift(2분·5개·민감) 그대로 재사용, 파일·캡처는 ShelfItem으로 통합 모델
  • 로그에 내용·파일명 원문을 남기지 않는다(기존 [HARD] 유지)
작업량(대략)
  • 핸들·패널 껍데기 + 탭 0.5일 · 파일 탭 0.5일 · 캡처 3모드 1.5~2일 · 설정·연결 0.5일

9. 정해 주실 것 이 4개만 정하면 구현 들어갑니다

  • 이름 — QuickShelf(추천) / Edge Hub / QuickPocket / 직접
  • 핸들 기준 — 화면 가장자리(삼성 방식, 추천) / QuickTalk 창 안
  • 입력창 ＋ — 완전히 제거(추천) / 남겨두고 패널과 병행
  • 캡처 구현 방식 — 자체 단축키 ⌥⇧3/4 + ScreenCaptureKit(추천) / 기본 단축키 결과 감시(Desktop·클립보드)
