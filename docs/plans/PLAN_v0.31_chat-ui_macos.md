## 1. 현재 구현 실측 (2026-11-05 코드 기준)

### 1.1 창·상단
- `buildPanel()`: `460×560`, `contentMinSize 420×420`, style `[.titled, .fullSizeContentView, ...]`.
- 타이틀바가 **그대로 보인다** — "QuickTalk" 텍스트 + traffic light(28pt) + 그 아래 헤더(약 38pt) = 상단 크롬 **약 66pt**.
- 헤더 컨트롤 **12개**(좌→우): 보라 점 · 제목(편집) · 🔖핀 표시 · 비서 칩 · ⌘Space 힌트 · 읽어주기 중지(조건) · 📌항상 위 · 🧠공통 메모리 · 🔖보관 · ✎새 대화 · ◫퀵셸프 · 탭 3개(대화/보관함/설정).
- `ContentChat` 본문 폰트 13pt(`MarkdownText.baseSize = 13`), 질문 13pt(시스템 기본).

### 1.2 메시지
- 응답: `MarkdownText` + `.padding(9)` + `Color.primary.opacity(0.055)` 배경 + corner 12.
- **오른쪽 레일**: 응답 오른쪽에 복사·읽어주기 버튼 HStack(24pt×2)이 **항상 자리를 차지**한다. 질문은 `padding(.trailing, 26)` + `⋯` 오버레이 → 본문 폭이 약 **50pt** 줄어든다.
- 질문: 오른쪽 정렬, accent 16% 배경 + 테두리, 13pt. `⋯` 메뉴 **항상 보임**.
- 시간: 응답 아래 왼쪽 10pt "12분 전 · 4.3초". 복사/읽어주기는 오른쪽 별도 열.

### 1.3 입력독
- 오른쪽 버튼 3개 + 전송(각 26pt): 🪟창 연결 · 🌐웹 검색(이번 질문) · 🎤음성 · ↑전송.
- 왼쪽 아래 비서 버튼(26pt), 입력 시작점 `leading 48`.
- 활성 상태: 웹 검색 = 보라 채움, 음성 = 빨강, 전송 중 = ⏹.

### 1.4 동작 성격(중요)
- **웹 검색 강제**: 요청을 시작할 때 `forceWebSearch = false` 로 **자동 해제** — "이번 질문 한정".
- **창 연결**: 시트에서 창을 고르는 **1회성**.
- **음성 입력**: 녹음 중 유지, 다시 누르면 중지 — **유지형**.

### 1.5 다중 대화 관련
- `UIStore` 에 `core: ConversationStore` 1개, `replyTask` 1개, `isReplying` **전역** 1개.
- 스트리밍 중 `guard self.conversation.id == convID`(4곳) — **다른 대화로 옮기면 그 답변은 버려진다**(부분 출력 소실).
- `openConversation` 은 응답을 취소하지 않는다 → 화면만 안 보이고, 다음 델타에서 guard로 종료.
- 반면 **예약 작업(`ScheduledRunRunner`)은 이미 별도 `ConversationStore` + Task로 병렬 실행**되고, `applyScheduledConversation` 으로 보관함만 갱신한다 — 병렬 요청 자체는 이미 하고 있다.

### 1.6 QuickShelf
- 탭 3개(`ShelfTab`: 클립보드/파일/캡처), 기본 = 클립보드.
- `store.archive` 를 이미 들고 있다 → **대화 목록 탭 추가는 데이터 추가 없이 가능**.
- 선택 시 `store.openConversation(c)` + `closeShelfDock()` 로 "고르면 닫힘" 구현 가능.

## 2. 레퍼런스 — 시리와 요즘 흐름

- 시리(스크린샷)는 **Liquid Glass**(WWDC25 · macOS 26 Tahoe에서 도입, 27에서 정착) — 창 전체가 하나의 유리 면, **제목 텍스트 없이 traffic light만**, 콘텐츠가 위까지 이어지고, 컨트롤은 필요할 때 떠오른다.
- SDK 확인: `glassEffect(_:in:)` 는 **macOS 26.0+**(현재 SDK 27.2). 우리 배포 타깃은 **14.0** → `if #available(macOS 26, *)` + 미지원은 `.ultraThinMaterial` 폴백.
- 2025~26 AI 채팅 UI 공통 흐름:
  1. **콘텐츠 우선** — 크롬(툴바)이 사라지고 대화가 화면을 채운다.
  2. **점진적 노출** — 호버/포커스/단축키에서만 보조 동작.
  3. **대화 목록 상시 접근** — 사이드바 또는 QuickShelf 같은 허브.
  4. **입력독 단순화** — `+` 하나 + 전송, 나머지는 메뉴.
  5. **읽기 타이포 강화** — 응답 본문을 질문보다 크게.
- 내 판단: **구조(콘텐츠 우선·호버 노출·단순 입력독)는 그대로 가져오고, 유리 재질은 크롬에만 제한**한다. 긴 한글 본문에 반투명 유리를 깔면 대비·가독성이 떨어지고, 스크롤 성능에도 불리하다. 본문은 불투명/근불투명, 툴바·퀵셸프·플로팅 칩만 glass.

## 3. 제안 — 화면별

### 3.1 타이틀바 = 제목 + 비서 (버튼은 호버)
```
● ● ●        Q3 리포트 정리   ·  🤖 다미            [호버 시 →  ⏹ 📌 🧠 🔖 ✎ ◫  ⌘Space   ⋯]
└ traffic light(시스템) ┘   └ 항상 보임 ┘              └ 평소 투명, 상단 44pt에 마우스 오면 페이드 인 ┘
```
- `titleVisibility = .hidden`, `titlebarAppearsTransparent = true` (이미 `.fullSizeContentView`).
- 제목은 클릭하면 이름 변경(현재와 동일), 비서는 기존 메뉴 그대로.
- 호버 영역은 **상단 44pt**로 한정(본문 읽다가 실수로 뜨지 않게). 메뉴가 열려 있거나 키보드 포커스가 상단에 있으면 유지.
- 평소 숨는 것: ⌘Space 힌트, 읽어주기 중지(읽는 중엔 표시), 📌, 🧠, 🔖, ✎, ◫, 탭 3개.
- **안전장치**: ① 설정에 "툴바 항상 보기" 토글 ② `⋯` 메뉴에 같은 동작 전부 ③ 첫 실행 1회 "상단에 마우스를 올리면 도구가 보입니다" 힌트.
- 보관함·새 대화·설정 탭은 **QuickShelf/⋯ 메뉴로 이동** → 상단에서 2~3개 아이콘 감소.

### 3.2 응답 = 전체 폭 + 하단 메타
- 응답 배경 카드 제거(또는 3% tint만), 좌우 여백 20pt, `baseSize 15`, 줄간 4.
- 하단 한 줄(높이 20 고정, 레이아웃 흔들림 방지):
  - 왼쪽: `12분 전 · 4.3초` (10.5pt secondary)
  - 오른쪽: 복사 · 읽어주기 (호버 시 페이드 인)
- 스트리밍 중에는 메타 줄 숨김, 완료 후 표시. 복사됨 체크는 1.2초.
- 출처 카드·도구 카드는 지금처럼 전체 폭.

### 3.3 질문 = 말풍선
- 오른쪽 정렬, 최대 폭 82%, accent 18% 채움, **꼬리**는 오른쪽 아래(작은 삼각형/연속 곡선).
- 13.5pt, 내부 여백 10×12.
- `⋯` 메뉴는 **말풍선 바깥 오른쪽**, 호버 시에만. 컨텍스트 메뉴(우클릭)는 유지 — 호버를 몰라도 접근 가능.
- 첨부 썸네일은 말풍선 안/위에 그대로.

### 3.4 입력독 — 도구 메뉴 하나
```
[🤖]  무엇이든 물어보세요                                    [＋]  [↑]
                                                          └ 클릭 → 창 연결 / 웹 검색 / 음성 입력
```
- `＋`(도구) 하나로 통합. 메뉴 항목은 **아이콘 + 이름 + 상태**:
  - 창 연결 — 1회성(시트)
  - 웹 검색 — 이번 질문 한정(체크, 전송하면 자동 해제)
  - 음성 입력 — 유지형(체크, 다시 누르면 해제)
- 유지형이 켜져 있으면 `＋` 버튼이 **그 아이콘으로 바뀐다**(🎤 빨강 / 🌐 보라 + 작은 점). "활성 아이콘을 다시 누르면 해제"는 메뉴 안에서 처리(실수 방지 위해 버튼 클릭은 항상 메뉴 열기).
- 왼쪽 비서 버튼은 그대로(요청대로 유지).

### 3.5 창 크기·타이포
- 기본 `400×560`, 최소 `380×420` (현재 460×560 / 420×420).
- 상단 크롬 66 → **40pt** (타이틀바+헤더 통합), 하단 여백 10 유지.
- 응답 15pt / 질문 13.5pt / 메타 10.5pt / 코드 13pt(응답 기준 -2).
- 좁은 창에서 표·코드가 깨지지 않도록 코드 블록은 가로 스크롤 유지(현재 동작 확인 필요).

### 3.6 QuickShelf — 대화 허브
- 탭 추가: **대화 | 클립보드 | 파일 | 캡처**, 기본 = **대화**.
- 대화 탭 맨 위: `＋ 새 대화` (클릭 → 새 대화 + 셸프 닫힘).
- 그 아래: 보관함(진행 중 → 최근 순), 각 행에 비서 이모지·제목·상대 시간·**응답 중 점**.
- 행 클릭 → 그 대화로 이동 + 셸프 자동 닫힘.
- 상단에서 사라지는 아이콘: 보관함, 새 대화 (+ 설정 탭도 `⋯`/허브로).

## 5. 다중 대화 — 조사 결론

### 5.1 가능한가
- **가능하다.** 요청은 대화별로 독립이다. 지금도 예약 작업과 대화 응답이 동시에 돌고 있다.
- 단, 제공자별 제약:
  - 원격(OpenAI·Anthropic·Gemini 등): 병렬 OK, 계정 rate limit만 주의.
  - Ollama: `OLLAMA_NUM_PARALLEL` 기본값이 1인 버전이 있어 **두 번째 요청이 큐에 대기**할 수 있다(실패는 아님).
  - Apple FM(온디바이스): 동시 세션 제한 가능성 — 두 번째 요청이 실패하면 "이 기기에서는 한 번에 하나" 안내 + 큐잉.
- 즉 "AI가 다중 요청을 못 한다"가 아니라 **우리 앱이 한 세션 상태만 들고 있어서** 못 하는 것이다.

### 5.2 필요한 변경
1. `UIStore` 의 실행 상태를 **`ChatSession`(대화별)** 으로 분리:
   - `core: ConversationStore`, `replyTask`, `isReplying`, `streamingTurnID`, `replyStartedAt`,
     `networkRetryStatus`, `pendingSchedule`, `agentApproval`, `draft`, `attached`, `forceWebSearch`, `inputHeight`.
2. `UIStore` 는 `sessions: [UUID: ChatSession]` + `activeID` 만 갖고, 화면은 active 세션을 관찰.
3. 스트리밍 완료 시 해당 세션 → 보관함 갱신(`applyScheduledConversation` 과 같은 경로).
4. 전역으로 남길 것: 읽어주기(스피커 하나), 음성 녹음, 전역 단축키, 예약 실행.
5. UI 표시: 보관함 행 **응답 중 점**, 메뉴바 아이콘 배지(선택), 백그라운드 완료 시 알림(선택).

### 5.3 단계
- **6a (선행, 동작 변화 0)**: 상태 분리 리팩터링 + 기존 테스트 840개 유지 + 세션 단위 테스트 추가.
- **6b**: 동시 실행 허용 + "응답 중" 표시 + 대화 전환 시 스트림 유지.
- 예상: 6a 중~대(UIStore 2,300줄 중 실행 경로 대부분 이동, 1,000~1,500줄), 6b 중(300~500줄).
- 위험: 승인 카드·도구 실행이 대화별로 갈라져야 함, 자동 정리 타이머 중복, 메모리 사용 증가(동시 스트림 수 제한 2~3개 권장).
