# PLAN_v0.12_chat-window_macos.md
> 생성일: 2026-10-19 | 플랫폼: macos | 작성자: OpenCode
> 목표: 대화 창을 "Siri 새 대화 창" 수준으로 정리 — ① 클립보드 스트립(최근 1~2분 텍스트·이미지) ② 창 크기 가변 ③ 입력독 정리(+ = 파일·이미지 첨부, 🎤 = 음성)

## 1. 배경 (사용자 분석 요청)
- 기존 대화 창은 Siri 새 대화 창(중앙 워터마크 + `+` / 입력 / 🎤 하단 입력독)처럼 쓰고 싶었음
- 시작 방식은 2가지: (1) 단축키 → 창 (2) **마우스 포인터 옆 pill**(참고: Siri "Siri에게 물어보기" 칩)
- 신규 기능: **최근 1~2분 내 복사한 텍스트/이미지**를 창에 띄우고, 클릭하면 텍스트는 입력창 삽입 / 이미지는 첨부
- 이 기능 때문에 창 크기 문제가 생김 → 고정이냐 가변이냐
- 확인된 현재 상태: `📋` 버튼은 "클립보드 검색 레이어(목업-0.1 준용)" **스텁 텍스트만** 표시, `NSPasteboard` 감시 코드 없음.
  창은 `styleMask`에 `.resizable`이 있으나 `ContentView.frame(460×560)` 고정이라 사실상 고정

## 2. 사용자 확정 (2026-10-19, 목업 `docs/mockup-0.4-chat-window.html` 기준)
| 항목 | 결정 |
|---|---|
| 스트립 위치 | **입력독 바로 위** |
| 창 크기 | **가변** (최소 420×420, 자유 리사이즈, 크기 기억) |
| 유지 시간·개수 | **2분 · 최대 5개** (넘치면 오래된 것부터 제거, 만료 시 자동 소멸) |
| 민감 항목 | **기본 마스킹(••••) + 클릭 공개** |
| 포인터 pill | **다음 단계로 분리** (이번 범위 아님) |

## 3. 범위
- 신규 `QuickTalkApp/ClipboardService.swift`: `changeCount` 폴링(0.7s)으로 최근 항목 수집, TTL 2분·최대 5개, 민감 판정, 공개 상태
- `UIStore`: `clipboard` 서비스 보유 + 텍스트 삽입 / 이미지·파일 첨부 헬퍼
- `ContentView`: ① 스트립(입력독 위) ② 입력독 재구성(`＋` 메뉴 = 파일·이미지·클립보드 레이어 / 입력 / 🎤 / ↑) ③ 고정 frame → 가변(min 420×420, ideal 460×560)
- `QuickTalkApp`: 패널 `contentMinSize` + `setFrameAutosaveName`(크기·위치 기억)
- `MenuBarHubView`: 공유 설정 카드 최대 폭 520pt 제한(창이 넓어져도 카드가 늘어나지 않게)
- 보관함·설정 탭: 같은 창에서 함께 늘어남(별도 창 분리 없음)

## 4. 창 크기 / 레이아웃 규칙
- 입력독·클립보드 스트립 = **하단 고정**, 대화 본문만 늘어남
- 최소 420×420 (그 이하로 줄이면 입력독이 본문을 덮음), 기본 460×560, 크기는 자동 저장
- 넓은 창에서 설정 카드가 가로로 늘어나지 않도록 **최대 520pt 중앙 정렬**
- 보관함 탭: 늘어난 만큼 목록이 더 보임(스크롤 유지)

## 5. 성능 예산
- 폴링 0.7초 = 타이머 1개 + `changeCount` 정수 비교(문자열/이미지 디코딩은 **변경 시에만**)
- 이미지 데이터는 썸네일용으로 축소 보관(긴 변 160px, PNG), 항목 최대 5개 → 메모리 영향 ≤ 수 MB
- Chat 창 크기 기억은 `NSWindow` 자동 저장 사용(별도 파일 없음)

## 6. 개인정보·보안 ([HARD] 9 준수)
- 클립보드 **내용은 로그·캡처에 남기지 않는다** — 로그는 개수/종류만
- 비밀번호 관리자 마커(`org.nspasteboard.ConcealedType`/`TransientType`)는 **수집 제외 또는 민감 처리**
- 민감 판정: 마커 + 패턴(password, secret, api key, token, otp, 주민번호, 카드번호 등) → 기본 마스킹, 사용자가 눌러야 표시
- 스트립은 클립보드를 **읽기만** 한다(쓰기·수정 없음)

## 7. 에러 코드
- 신규 없음. 기존 `E-MAC-RENDER-0001`(렌더/표시 오류) 재사용

- 빌드 → `~/Applications/QuickTalk.app` 배포 → 캡처로 확인: 스트립 표시/클릭 삽입/만료, 창 리사이즈 시 본문만 늘어남, 설정 카드 520pt 제한
- 실사용 확인(사용자): 클립보드 복사 → 스트립 등장 → 클릭 → 입력창 삽입, 2분 후 사라짐

### 8.2 구현 중 고친 결함
- 앱 시작 시점에 이미 복사돼 있던 내용이 수집되지 않아 스트립이 비어 보임 → `start()`에서 1회 수집
- 중첩 `ObservableObject`(ClipboardService) 변경이 부모 뷰(UIStore 관찰)로 전달되지 않아 항목 소멸 후에도 스트립 껍데기가 남음 → `UIStore`가 `clipboard.objectWillChange`를 전달
- 칩의 `✕`가 본문 클릭 영역과 붙어 오조작 가능 → 구분선 + 16pt 히트 영역으로 분리
