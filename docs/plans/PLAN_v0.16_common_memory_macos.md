# PLAN v0.16 — 공통 메모리 (P1~P3, macOS)

> 상태: **P1~P3 구현 완료** (2026-10-21 05:20 KST) — 사용자 실측 대기
> 관련: T-71 대화 기억 정리, `docs/plans/PLAN_v0.14_websearch_macos.md` P3, `docs/HANDOFF.md`

## 1. 문제

기존 `ConversationMemory`는 **대화별 요약**이다. 대화가 길어지면 오래된 턴을 요약해
전송량을 줄이지만, **새 대화로 넘어가면 사용자의 변하지 않는 사실**(맥 사양·개발 환경·말투 선호)을
모델이 다시 묻는다. 사용자는 매번 같은 설명을 반복하게 된다.

해결: **공통 메모리** — 사용자가 설정에서 직접 쓰고 관리하는 전역 사실을
매 요청의 프롬프트 앞에 넣는다. 모델을 학습시키는 것이 아니라 **프롬프트 문맥**으로 주입한다.

## 2. 결정

| 질문 | 결정 |
|---|---|
| 적용 범위 | **모든 대화** — 단, 대화별 🧠 토글로 그 대화만 끌 수 있다 |
| 저장 위치 | `~/Library/Application Support/QuickTalk/memory.json` (대화 기록과 분리) |
| 항목 수 | 제한 없음(실용상 수십 개). 요청에는 **토큰 예산**까지만 |
| 기본 예산 | **800토큰**(400/800/1600/3200 선택) |
| 기본 방식 | **항상 모두 포함** — 켜 둔 항목을 앞에서부터 |
| 관련 검색 | **로컬 해시 임베딩**(외부 API 없음) + 태그/제목 보정 |
| 민감정보 | 자동 검열하지 않음. 설정에 경고만 표시(원격 전송 사실 포함) |
| 대화 요약과 관계 | 별개. 공통 메모리 → 대화 요약 → 최근 원문 → 질문 순서 |

## 3. 데이터 모델

```swift
public struct GlobalMemoryEntry: Codable, Identifiable, Equatable {
  public var id: UUID
  public var title: String          // 비우면 본문 첫 줄
  public var content: String
  public var tags: [String]         // "#" 없이 저장
  public var enabled: Bool
  public var alwaysInclude: Bool    // 관련 모드에서도 항상
  public var createdAt: Date
  public var updatedAt: Date
}
```

- 모든 필드는 `decodeIfPresent`로 읽어 옛/외부 JSON과 호환한다.
- 저장 봉투: `{ "version": 1, "entries": [...] }`. 배열만 있는 JSON도 가져올 수 있다.
- `Conversation.commonMemoryDisabled: Bool?` — 구버전 기록은 `nil`(사용)로 읽힌다.

## 4. 동작

### 4.1 요청 프롬프트

```
[사용자 공통 메모리]
아래는 사용자가 모든 대화에 적용하려고 저장한 사실이다. 이미 알고 있는 정보로 취급하고
같은 내용을 다시 묻지 않는다. 메모리와 이번 질문이 충돌하면 질문의 최신 내용을 우선한다.
메모리에 없는 내용을 지어내지 않는다.
- [내 맥 사양] MacBook Pro M4 Pro 24GB … (#개발 #하드웨어)
- [답변 선호] 항상 한국어로, 결론부터 짧게 … (#말투)

[이전 대화 요약] …        ← 대화별(있을 때)
[실시간 웹 검색 결과] …    ← 검색을 쓸 때
질문: …
```

- 항목은 **사용자가 정한 순서**대로 들어간다. 위/아래 버튼으로 바꾼다.
- 예산을 넘으면 뒤쪽 항목부터 빠지고, 마지막 항목은 본문을 줄여 `…`로 표시한다.
- `항상 포함`은 관련 모드에서도 질문과 무관하게 들어간다.

### 4.2 관련 항목만 (P3)

외부 임베딩 API 없이 도는 **결정론적 해시 임베딩**을 쓴다.

1. 소문자화·구두점→공백.
2. ASCII는 단어(2자 이상), 한국어/한자/일본어는 **2-gram**을 특징으로 만든다.
3. FNV-1a 64로 2,048차원에 부호와 함께 투영하고 L2 정규화.
4. 질문·항목 벡터의 cosine × 0.8 + 제목 일치 0.12 + 태그 일치 0.08.
5. 점수 ≥ **0.22** 또는 `항상 포함`만 주입. 관련 항목이 없으면 **아무것도 넣지 않는다**.

> 정확한 신경망 임베딩은 아니다. 오프라인·무료·빠르고 테스트가 고정된다는 장점이 있다.
> 모델 임베딩(예: Ollama embedding)은 후속 과제다.

### 4.3 대화별 끄기

- 대화 창 헤더의 🧠 버튼: 켜짐(보라)/꺼짐(회색 빗금).
- 설정의 항목은 그대로 두고 **그 대화의 요청에서만** 제외한다. 기록에 저장된다.

### 4.4 관리 UI (설정 › AI › 공통 메모리)

- 전역 토글, 방식(항상/관련), 토큰 예산, 현재 예산 요약.
- 검색(제목·본문·태그), 추가/편집/삭제, 사용 토글, 항상 포함, 순서 변경.
- 행마다 예상 토큰 표시.
- JSON 가져오기/내보내기(같은 ID는 건너뛰고 새 항목만 추가).
- 원격 전송·민감정보 경고 캡션.

## 5. 토큰·예산

- 토큰 추정은 `ConversationMemory.estimateTokens`를 재사용한다(보수적).
- 머리말·규칙 비용 약 70토큰 + 항목당 12토큰.
- `ConversationMemory.fitHistory(extraTokens:)`로 **대화 기록 예산에서 공통 메모리 몫을 먼저 예약**한다.
  검색을 켜면 검색 문맥 몫 400토큰도 함께 예약한다.
- Apple FM(4,096)에서도 800토큰 예산이면 최근 원문 4개와 함께 들어간다.

## 7.1 2026-10-21 감사 반영

- **프롬프트 비용**: `headerText()`를 실제로 세어 `fit(reserved:)`에 넘긴다(언어 전환 시에도 예산 정확).
- **성능**: 항목 임베딩을 `MemoryEmbeddingCache`(128개)에 캐시하고, 질문 벡터는 한 번만 계산. 긴 본문 자르기는 이진 탐색.
- **저장 보호**: 원자적 쓰기 + `0600`. 디코딩 실패 시 원본을 `memory.json.corrupt`로 남기고 빈 목록으로 시작(다음 저장이 원본을 덮지 않음).
- **설정 내성**: 알 수 없는 enum 값은 그 필드만 기본값으로 두고 나머지 설정은 보존.
- **검색 연동**: 실제 검색 컨텍스트가 400토큰을 넘으면 기록을 다시 맞춘다(작은 컨텍스트 모델 보호).
- **한계는 그대로**: 어휘 기반 동의어 약함, 원격 전송, 민감정보 자동 마스킹 없음, 장기 대화 검색 별개.

## 8. 한계·후속

- 모델 임베딩이 아니라 어휘 기반이라 **동의어**에 약하다(예: "노트북" ↔ "맥북"). 태그를 함께 쓰길 권장.
- 메모리는 프롬프트 앞에 붙으므로 **원격 프로바이더에는 전송된다**. 민감정보 금지 안내만 있고 자동 마스킹은 없다.
- 항목별 사용 빈도·자동 만료·버전 기록은 미구현.
- 대화 기록 전체를 대상으로 한 장기 기억 검색은 별개 과제다(공통 메모리는 사용자 작성 사실만).
