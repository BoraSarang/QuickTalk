# PLAN v0.36 — 실행형 에이전트 1단계: 답변 → 실행 (macOS)

> 상태: **계획(구현 전)** · 2026-11-11 · 크기: **M** (v0.36 본편), 뒤에 스킬·브라우저 로드맵 포함
> 계기(사용자 관찰): *"질문 답변도 좋지만 거의 이거 해줘. '이거 어떻게 하냐?'로 시작해서 '그거 해줘'로 끝나는 용도가 더 어울리네."*
> 원칙: 새 앱을 만드는 것이 아니다. 이미 있는 **AgentExecutor · 승인 카드 · 되돌리기 · 예약** 위에 **한 조각**을 얹는다.

---

## 1. 목표 (1줄)

답변 아래 **[이대로 실행]** 하나로 "설명"이 "실행"으로 이어지고, 실행 과정·산출물·중단·되돌리기가 한 화면에서 끝난다.

---

## 2. 지금 있는 것 (사실 확인)

- **도구 5묶음**: `shell` / `read_file`·`list_dir`·`processes`·`screenshot` / `web_search`·`web_fetch` / `ui_snapshot`·`ui_action` / 예약(`schedule_*`).
- `AgentRunner` 루프(최대 12스텝) → `AgentExecutor`가 **샌드박스 실측 → 승인 카드 → 실행 → 감사 로그 → 되돌리기**를 담당.
- 비서별 도구 토글(`PersonaTools`: read/web/shell/write/ui), 예약 실행, 리포트 저장.
- 답변 하단 hover 액션은 **복사·읽어주기**뿐 — **실행으로 이어지는 입구가 없다.**
- 스킬·MCP·브라우저 도구는 **없다.** (이 계획에서 스킬·브라우저는 설계만 확정)

## 3. v0.36 — P0: 답변 → 실행 (이번 버전의 완료 기준)

### 3.1 동작

1. assistant 답변에 마우스를 올리면 복사 옆에 **[▶ 이대로 실행]** 이 나타난다.
2. 누르면 **같은 대화**에 사용자 턴이 하나 붙고, 그 턴은 `executesTurnID` 로 **실행 턴**임을 기록한다.
   - 말풍선은 짧게: `이 답변대로 실행해 주세요.`
   - 모델 프롬프트에는 아래 **실행 계약**을 덧붙인다(말풍선에는 넣지 않는다).
3. 실행 턴은 **기존 에이전트 루프를 그대로** 탄다. 도구 카드·승인·중단·되돌리기·감사 로그가 자동으로 따라온다.
4. 실행 결과 답변에는 **[이대로 실행]** 을 다시 달지 않는다(무한 반복 방지). 다시 하려면 턴 메뉴의 [다시 실행].

### 3.2 실행 계약 (프롬프트)

```
방금 네가 답한 절차를 실제로 실행해 주세요.
- 먼저 실행할 단계를 3~6개로 짧게 보여 주세요.
- 각 단계는 지금 이 Mac에서 실제로 실행 가능한 것이어야 합니다.
- 되돌릴 수 없는 동작(삭제·덮어쓰기·전송·결제)은 실행 전에 무엇이 바뀌는지 한 줄로 알려 주세요.
- 도구가 필요하면 지금 실행하고, 결과까지 확인한 뒤 최종 보고를 쓰세요.
- 실행할 수 없으면 이유를 한 줄로 말하고 멈추세요.
```

### 3.3 구현 지점

| 위치 | 변경 |
|---|---|
| `Sources/QuickTalkCore/ExecutionPrompt.swift` (신규) | `visibleText`(짧은 말풍선) · `contract`(모델용) · 길이 상한. 순수 문자열이라 테스트 쉬움 |
| `Sources/QuickTalkCore/Models.swift` | `Turn.executesTurnID: UUID?` — 옵셔널이라 구버전 기록도 그대로 디코드 |
| `QuickTalkApp/UIStore.swift` | `send(executionOf:)` — `core.submit` 에는 짧은 말풍선, 모델 `prompt` 에는 계약을 덧붙인다. `isReplying` 가드 재사용 |
| `QuickTalkApp/ContentView.swift` | `answerFooter` 에 버튼. 표시 조건: `settings.agentToolsEnabled && !t.isExecutionResult && !store.isReplying` |
| `docs/DESIGN.md` §9 | 답변 액션 표에 [이대로 실행] 추가 |

**표시 조건 세부**
- 비서가 셸·쓰기·앱 조작을 **모두 꺼** 두었으면 버튼은 비활성이 아니라 **숨긴다**(할 수 없는 일을 권하지 않는다).
- 예약 실행으로 만들어진 리포트 턴, 오류 턴, 실행 턴의 결과에는 버튼을 달지 않는다.
- Apple FM은 에이전트 도구가 shell/read/list로 제한되므로 실행 결과가 제한적일 수 있다 — 버튼은 그대로 두되, 첫 사용 시 한 줄 안내.

### 3.4 안전

- **자동 승인 없음.** 답변에서 "이렇게 하면 된다"고 말한 것과 실제 실행은 별개다. 실행 턴도 기존 승인 카드를 그대로 띄운다.
- 실행 턴은 **새 승인 범위를 만들지 않는다.** 같은 대화에서 이미 허용한 범위만 재사용한다.
- `rm -rf` 등 파괴 명령은 기존 `RiskClassifier`·2차 확인 그대로.
- 중단은 기존 [중단], 되돌리기는 기존 `UndoStack` — 새 안전장치를 만들지 않는다.

### 3.5 검증

- **단위**: `ExecutionPrompt` 문구·길이, `Turn` Codable 구버전 디코드, 버튼 표시 조건(순수 함수로 분리).
- **QA 하네스**: `--qa-execute-button`(오프스크린 렌더), `--qa-execute-dry-run`(모의 에이전트로 실행 턴 1회 — 도구 호출 없음).
- **수동 3종**: ① 디스크 정리 ② 폴더 파일 정리 ③ 웹 조사 → 리포트. 각 1회, 승인 카드 수·중단·되돌리기 확인.
- **예산**: 답변 렌더 변화 없음(버튼은 hover 시에만), 프롬프트 **+400자 이내**.

## 5. v0.37 — 스킬 (설계 확정)

### 5.1 스킬이란

`SKILL.md`(YAML frontmatter + 본문) + 선택 `scripts/`·`references/`·`assets/`.
**OpenCode/Claude 계열 스킬 폴더와 같은 모양**이라, 사용자가 이미 가진 스킬을 폴더째 가져올 수 있다.

```markdown
---
name: web-research
description: 여러 사이트를 조사해 출처가 있는 리포트 파일로 저장한다
when: 최신 정보를 비교하거나 근거가 필요할 때
tools: [web_search, web_fetch, shell]   # 좁히기만 가능
version: 1
risk: read
---
본문 — 절차, 주의점, 스크립트 사용법
```

### 5.2 저장·등록

- **번들**: `Resources/Skills/<id>/` (앱 리소스, 읽기 전용)
- **사용자**: `~/Library/Application Support/QuickTalk/Skills/<id>/`
- `SkillRegistry`(Core): 실행 시 스캔 + frontmatter 파싱, 실패한 스킬은 건너뛰고 경고. 상한 — 200개, 본문 64KB, 스크립트 20개.
- 가져오기: **"폴더에서 가져오기"** — `SKILL.md` 가 있는 폴더만. 원격 마켓 없음(v1).

### 5.3 프롬프트·실행 (점진 공개)

- system prompt에는 **이름 + 설명 + 언제** 한 줄씩만 넣는다(예산 **1,200자**). 본문은 넣지 않는다.
- 본문은 새 도구 **`read_skill(name)`** 로 필요할 때만 읽는다(읽기 전용, 승인 카드 없음, 감사 기록).
- 스킬 스크립트는 **기존 `shell` 로 실행**한다 — 샌드박스·승인·되돌리기·감사가 그대로 적용된다. **새 실행 경로를 만들지 않는다.**
- `tools:` frontmatter는 **좁히기만** 가능(비서 도구와 교집합). 스킬이 권한을 넓힐 수 없다.
- `/스킬` 슬래시: 목록에서 고르면 `‘이름’ 스킬로 …` 가 입력창에 채워진다.

### 5.4 신뢰·보안

- 전역 `skillsEnabled` 기본 **꺼짐**. 가져온 스킬은 사용자가 [사용]을 눌러야 활성화된다.
- 스킬 본문은 **사용자가 신뢰한 절차**로 취급하되, 전역 안전 규칙이 항상 우선한다(프롬프트 뒤에 재확인 문장).
- 경로 탈출·심볼릭 링크 차단, Keychain 접근 금지, 스크립트 실행 카드에 **스킬 이름·경로** 표시.
- 스킬은 코드 서명 대상이 아니다 — 출처를 UI에 표시하고 **자동 업데이트하지 않는다.**

## 6. v0.38 — 브라우저 손 (ego-browser)

### 6.1 결론

**가능하다.** 지금도 `shell` + 스킬로 ego-browser를 부를 수 있다. 다만 안정성·승인 피로 때문에 **2단계**로 간다.

- **P3a (v0.38): 스킬 + shell PoC** — 번들 스킬이 정확한 명령을 가르치고, 모델이 shell로 실행. **새 도구 0개.**
- **P3b (v0.39): 전용 `browser` 도구** — 실행 1건당 승인 1장, 구조화된 action 로그, 도메인 가드. PoC에서 승인 피로·실패율이 확인될 때만.

### 6.2 왜 전용 도구인가 (P3b)

- shell은 **명령 1건당 승인** → 브라우저 작업은 5~15스텝 → 승인 피로가 크다.
- ego-browser는 Node 스크립트라 heredoc/quoting 실패가 잦다. 앱이 스크립트를 생성하면 재현성이 올라간다.
- 도메인 허용목록·최종 제출 확인·스크린샷 감사를 **도구 수준에서 강제**할 수 있다.

### 6.3 실행 환경 (중요)

- Finder에서 실행한 앱은 PATH가 짧다 → `~/.local/bin/ego-browser` 등 **절대 경로**를 실행 시 감지해 설정에 저장. `zsh -lc 'command -v ego-browser'` 로 1회 보정.
- ego-browser는 자기 데이터 폴더에 쓴다 → 기존 폴더 승인 범위와 별개로 **전용 샌드박스 프로필**(ego 데이터 쓰기 + 네트워크 + 산출물 폴더)을 쓴다.
- `ego-browser skill` 의 버전(현재 **v2.2.0**)을 확인하고, 가이드가 바뀌면 스킬 본문을 갱신. heredoc이 막히면 `-e` 를 쓴다.
- 한 번에 **TaskSpace 1개**(목표 1개). 공간은 자동 삭제하지 않는다 — 사용자의 로그인 상태를 보존한다.

### 6.4 안전 3단계

- **T0 읽기**: 열기·스냅샷·텍스트 추출·스크린샷 — 도메인 최초 1회 승인 뒤 자동.
- **T1 조작**: 입력·클릭·페이지 이동 — 실행 1회 승인(대상 도메인·동작 목록 카드).
- **T2 되돌릴 수 없음**: 전송·결제·삭제·게시 — 실행 직전 요약 확인, **예약 실행에서는 금지**.
- 로그인·2FA·결제는 **사용자에게 넘긴다**(자동 입력 금지). 완료 후 [계속]을 누르면 재개.

### 6.5 페이지 내용은 데이터다

- 페이지 텍스트는 **지시가 아니다.** 모델 지시문에 명시하고, 도구 출력에도 "신뢰하지 않는 데이터" 라벨을 붙인다.
- 하드 스톱은 프롬프트가 아니라 **도메인 허용목록 + T2 확인 + 감사 스크린샷**이다.

### 6.6 감사·정리

- 실행마다 `Application Support/QuickTalk/BrowserRuns/<id>/` 에 동작 목록·최종 URL·스크린샷. 보관 30일.
- [브라우저 공간 정리] 수동 메뉴만 둔다(자동 삭제 없음).

## 7. 활용 시나리오

1. **"디스크 왜 부족해?"** → 답변 → 이대로 실행 → 휴지통 이동·정리, 되돌리기 가능.
2. **"이 폴더 사진 정리해줘"** → 계획 카드 → 실행 → 결과 리포트.
3. **"경쟁사 3곳 가격 비교해서 표로"** → 브라우저 T0 + 리포트 파일.
4. **"매일 아침 이 사이트 새 글 요약"** → 예약 + T0만.
5. **"로그인해서 지난달 청구서 PDF 받아줘"** → 로그인은 사용자, 다운로드·정리는 앱.
6. **"이 저장소 클론해서 빌드하고 결과 알려줘"** → shell + 스킬(프로젝트 스캐폴딩) — 사용자가 말한 "프로젝트도 만들겠다"의 입구.
7. **"이 앱 설정 바꿔줘"** → 기존 `ui_snapshot`/`ui_action`.
